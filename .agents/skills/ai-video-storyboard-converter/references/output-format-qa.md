# AI视频分镜Prompt转换器_输出格式与质检清单

## 0. 文件用途

本文件是精确输出外壳、顶层字段集合、字段职责、整数秒求和、台词覆盖及正式交付 QA 的权威来源。

正式生成、续写、格式／台词／时长检查及任何完整正式修订稿按 `SKILL.md` 路由读取本文件。它不得覆盖 `main-converter-rules.md` 的范围、原文、优先级和容量规则，也不替代 `camera-performance-rules.md` 的镜头、表演和摄影方法。质检清单只用于内部自检；正式交付前必须执行当前任务适用的分项，不要求向用户显性输出。

---

## 1. 标准输出外壳详解

每个约 15 秒小段必须使用以下结构：

```text
[集数-场次] 小段X｜15秒

【约束铁律】：仅制作音效，不制作音乐，不制作字幕

整体视频采用：...

场景设定：地点：...｜时间：...｜具体光线与空间氛围：...

角色：
角色名[状态: ...][声音: ...]
角色名[状态: ...][声音: ...]

空间站位备忘：...

道具设定：...

[Context Lock - Do Not Render]: ...

镜头一
时间长度：...秒
景别：...
构图：...
机位运动：...
画面内容：...
台词：...
```

`15秒` 是默认时长；如按自然完成时长短于 15 秒，标题行时长必须改为实际总时长。每个镜头的 `时间长度` 使用整数秒，各镜头相加必须等于标题行总时长。

正式输出外壳是闭合的顶层字段集合。除非用户当前要求或项目规范明确增加项目级字段，否则不得新增、改名、删除或重排顶层字段。项目明确增加的顶层字段不视为格式污染。时长只由标题行总时长和各编号镜头的整数秒体现；不得临时新增 `【时长约束】` 等顶层字段。

默认不得删除、改名或重排：

- 标题行。
- 约束铁律行。
- 整体视频采用。
- 场景设定。
- 角色栏。
- 空间站位备忘。
- 道具设定。
- `[Context Lock - Do Not Render]`。
- 编号镜头和每镜时间长度。

不得改用其他前情字段名，最终前情字段必须保持 `[Context Lock - Do Not Render]`。

镜头字段应优先写可见画面、动作、站位、道具、光影和表演细节，少写解释性、流程性、制作说明性文字。默认不写 palette 或色号。

字段职责原则：

- 每项信息只进入最适合的一个主字段。
- 未获当前用户或项目规范明确确认时，不得在闭合外壳之外新增顶层字段；已明确确认的项目级字段按其项目规则保留。
- 场景级持续条件只在最适合的统一字段中声明一次，由该场景内镜头继承；单镜头只写变化或例外。
- 只有当前镜头生成或跨段连续性确实需要时，才在镜头正文或 Context Lock 中保留最小必要重复。
- 已由生成平台单独设置的画幅、分辨率或其他技术参数，默认不在 Prompt 正文和每条镜头中重复；目标模型明确依赖文字描述时，只在合适的全局字段中声明一次。
- 标题行总时长和每镜 `时间长度` 始终属于本 skill 强制字段，不因平台另有时长设置而省略。

## 2. 标题行规则

标题行格式：

`[集数-场次] 小段X｜15秒`

默认写 `15秒`；如果用户指定其他时长，或按主转换规则使用自然短时长，则写实际时长。

填写依据优先级：

1. 用户当前指定处理范围。
2. 剧本原文。
3. Project Instructions。
4. 启动资料表。
5. 已上传项目资料。

标题行应准确反映：

- 第几集。
- 第几场。
- 当前小段编号。
- 当前小段时长。

标题行只用于让用户识别正在处理哪一段。场景名、地点、时间、光线和空间氛围统一写入 `场景设定`。

不得保留占位语。  
不得编造无法确认的集数、场次或场景信息。

## 3. 音效 / 音乐 / 字幕控制

固定输出：

`【约束铁律】：仅制作音效，不制作音乐，不制作字幕`

含义：

- 此行是高于其他项目级约束的全局硬规则：可制作环境音、动作音、道具音、脚步声、呼吸声和空间声；不制作背景音乐，不制作字幕。
- G02 只约束表演描述和 `画面内容` 中的负面提示：只保留能阻止高概率生成错误、连续性错误或误表演的限制，并优先正面描述当前可见状态、需要发生的动作和声音表现。
- “无 Logo、无水印”等技术交付约束不受 G02 限制，按当前项目要求处理。
- Context Lock、场景设定和道具设定始终不是画面文字；应通过对应字段的用途说明处理，不必机械重复为负面约束。

在表演描述和 `画面内容` 中，不得为正常情况下本就不会发生的状态堆叠“未移动、未摘除、不提高音量”等负面提示；需要避免错误时，先写清当前可见状态和动作，再只补充必要的纠错约束。本条不削弱固定的 `【约束铁律】` 行，也不约束“无 Logo、无水印”等技术交付要求。

## 4. 整体视频采用字段填写规则

`整体视频采用` 用于承接项目稳定影像基调、当前小段全局适用的可执行影像处理，或项目指定的持续摄影质感。

应包含：

- 项目长期锁定的视觉质感。
- 当前小段全局适用的可执行影像处理。
- 项目明确指定的持续摄影质感。

填写原则：

- 控制在 1 行，最多 3 个风格点；按需选择，不机械填满三类组成。
- 保留项目已明确锁定且影响画面生成的风格。
- 根据当前小段压缩重写材质、影调和氛围描述。
- 不机械复制整段项目资料。
- 只写与画面生成直接相关的风格、光线、材质、镜头和色彩信息，不写制作说明、解释性文字、规则提醒或语言说明。
- 必须按当前场景调整视觉基调；白天、夜晚、室内自然光、烛光、病房冷光、街头夜色、普通对话或特殊能量场面应依据剧本和项目资料分别处理，不得机械复用上一段风格词。
- 不把单个客户样例风格写成所有项目默认。
- 默认不写 palette 或色号；即使项目资料提供色号，也不自动逐段写入。
- 只有用户明确要求“本项目必须保留色号 / 严格按 palette 输出”时，才作为项目级规则临时执行。
- 不写摄影设备或镜头品牌，除非当前项目明确要求。
- 当前场景具体光线、空间质感、天气或可见色彩效果应写入 `场景设定` 或镜头画面内容，不堆入 `整体视频采用`。

## 5. palette / 色号控制自检

默认不在分镜 Prompt 中写 palette 或色号。

检查项：

- 是否没有把 palette 或色号写成 skill 通用默认。
- 是否没有把色号写入镜头字段。
- 是否没有因为项目资料出现色号就自动逐段写入。
- 如果用户明确要求保留色号，是否只作为该项目级规则执行。

错误倾向：

- 编造不存在的色号。
- 把某项目色号用于其他项目。
- 将整段客户风格机械复制，导致当前小段 Prompt 过载。
- 用色号限制当前视频生成，导致画面不自然或过窄。

正确处理：

- 默认只写宽泛、可生成的视觉基调。
- 具体可见色彩效果写入场景或镜头画面，不写色号。
- 用户明确要求保留 palette / 色号时，才按项目规则执行。

## 6. 场景设定字段填写规则

格式：

`场景设定：地点：...｜时间：...｜具体光线与空间氛围：...`

必须写明：

- 地点。
- 时间。
- 可直接生成的物理环境：光源、方向、强弱、可见色彩、材质、天气、空气状态、空间尺度、纵深、遮挡和动线中与当前场景相关的内容。

“具体光线与空间氛围”只写可视、可生成的物理环境，不得写人物语气、心理状态、警觉程度、人物关系判断或剧情评价。紧张、压迫、危险等效果必须落实为可见的光线、材质或空间条件，不得只写抽象情绪结论。

`时间` 只记录画面可见的时间状态，并按当前项目规定的时间词表标准化。`CONTINUOUS`、`LATER`、`MOMENTS LATER` 等剧本连续性或剪辑标记不得机械复制或附加到时间字段；若标记含有可见时间信息（如 `THE NEXT MORNING`），提取该可见时间含义后按项目词表表达。连续性关系用于场景衔接和 Context Lock 判断。

地点描述一般可以承载内外景信息，不单独设置 `内/外` 字段。对于室内、封闭空间、梦境空间、抽象神域、虚拟空间或剧本未提供天气且画面不可见天气的场景，不得为了填充字段而编造天气；应优先写当前小段可见光线、空气状态和空间质感。确需说明外部天气不可见时可简短说明，但不得每段机械复读同一句天气不可见说明。

不得保留：

- 占位语。
- 模糊空泛表述。
- 无来源的推断。
- 与当前小段无关的场景说明。
- 后续剧情信息。

如剧本未写明天气或光线，但项目视觉风格已规定影调，可依据项目规则做合理场景化描述，不得写成新剧情事件。

场景设定必须与当前剧本场景一致；不得把上一段的夜间月光、特殊光效、室内光源或天气状态机械带入新的白天、普通对话、室外、室内或其他不同场景。

## 7. 角色栏填写规则

角色栏必须列出本段出场角色。

格式：

`角色名[状态: 当前状态和关键情绪][声音: 台词状态、语气、是否无台词、是否 OS/OV/VO]`

角色栏集中记录小段起始姿态、持续身体状态、伤情和简短可见情绪；不重复完整站位。眼神、呼吸、嘴唇、下颌、肩线、手部、重心等具体表演写入对应镜头。完整位置关系放到 `空间站位备忘`。

镜头正文只在角色状态发生可见变化或直接影响当前表演时写出该变化，不机械重复角色栏中的静态状态。

状态栏只包含：

- 当前可见姿态。
- 持续身体状态。
- 当前情绪的可见表现。
- 必要的长期状态。

声音栏只包含：

- 是否有台词。
- 台词语气。
- 可听见的音量、语速、距离、停顿、音色和尾音。
- 是否 OS / 内心独白 / OV / VO / 画外音。
- 若无台词，应写无台词，并说明以听戏反应、呼吸或身体反应表现。

声音栏可以保留简短情绪方向，但必须转成可执行的声音表现，不得只写心理解释；例如以音量、语速、停顿、音色或尾音说明，而非只写“紧张”或“克制”。

无台词角色的声音栏默认写：`无台词`。需要说明反应方式时，可写：`无台词，以目光或站位反应`。不得写成 `本小段无台词` 这类元说明。

角色栏和镜头正文都必须核对本段角色是否真的有台词。无台词角色不得写成开口、说话口型、对口型或类似发声状态；只能写听戏反应、呼吸、视线、身体停顿或站位变化。

枪声、爆炸声、环境声、道具声等不写成角色声音；应放入画面内容、场景氛围或由约束铁律隐含为音效。

角色长期状态必须持续继承，直到剧本或项目资料明确解除，例如受伤、失明、虚弱、昏迷、伪装身份、被束缚等。项目已提供角色资产时，`状态` 只写当前小段起始姿态、可见情绪或表情、伤情、持续身体状态，以及会影响当前动作的外观变化；稳定服装、固定首饰和已固化人物外观不得机械重复。未变化的资产信息由角色资产承载；必要的跨段服装或外观连续性可写入 Context Lock。没有角色资产的项目，可按当前项目资料保留生成所必需的外观信息。

角色视觉身份和对白称谓分开处理。角色栏、空间站位和镜头正文中的角色标识应保持制作上可追踪的稳定角色名；对白中的假名、尊称、误认称呼或临时称谓必须严格保留剧本原文。

不得只写：

- 情绪状态。
- 声音状态。
- 模糊角色称呼。
- 未核查的角色名。
- 不在本段出场的角色。

## 8. 空间站位备忘填写规则

空间站位备忘用于锁定空间关系，防止 AI 视频跳位。

只允许记录：

- 人物和作为空间锚点的关键物体的物理位置。
- 人物朝向和视线对象。
- 人物之间的距离。
- 前后、左右和遮挡关系。
- 动作完成后的空间落点。

有互动、对话、攻击、保护、追逐或压迫关系的角色之间，应写清相对距离，优先使用“约 X 米”。

空间站位备忘不得写灯光或环境氛围、人物情绪或伤势、表演状态、摄影构图、机位运动、道具生命周期细节、抽象权力关系或剧情解读。

关键道具的位置和状态以 `道具设定` 为主。只有道具同时构成空间锚点或遮挡时，才在空间站位中简短引用其物理位置，不重复归属、状态或生命周期信息。

不得让人物无原因：

- 从左跳到右。
- 从前景跳到后景。
- 从面对面变成背对背。
- 从坐着变成远处站立。
- 从室内瞬间变到室外。

若位置变化，镜头正文中必须写出过程。

## 9. 道具设定填写规则

道具设定默认中文为主。

必要时使用：

`中文道具名 / English visual keyword`

道具设定只收录当前小段发生实际交互、控制权变化、位置变化、状态或生命周期变化，或会直接影响当前生成连续性的物件。已固化在人物资产中的首饰、服装组件和随身装饰，以及已固化在场景资产中的固定陈设，默认不重复列入；只有本段发生上述变化或成为必要连续性锚点时才列入。

入栏道具应包含：

- 本段关键道具。
- 道具位置。
- 道具归属或控制者。
- 道具当前状态。
- 拿起、放下、交接、开启、关闭、损坏等生命周期变化。

道具设定只写关键道具、位置、归属、状态和生命周期；不写镜头级碎节奏，不重复人物状态、情绪、完整站位、场景氛围或镜头内容。

如果本段没有关键道具，写：

`道具设定：无关键道具。`

不得：

- 为填充而编造道具。
- 无故全部写成英文。
- 把专有道具翻译成另一个名字。
- 遗漏本段动作或连续性所需关键道具。
- 让关键道具凭空出现或消失。
- 只写道具名称，不写状态或位置。

## 10. Context Lock 填写规则

每段必须输出：

`[Context Lock - Do Not Render]: ...`

用途：

- 锁定当前小段所需的起始连续性。
- 锁定人物位置和姿态。
- 锁定影响当前画面的相对关系。
- 锁定关键道具状态。
- 锁定上一段尚未结束的动作状态。
- 防止 AI 视频把上一段状态重置。

首段也必须填写实际起始连续性，不得使用 `Scene start`、集数开始或结束等元信息代替具体状态。

后续段落只写：

- 上一段结束后的关键演员站位。
- 必要姿态和未完成动作。
- 关键角色距离。
- 道具连续性。
- 空间锚点。

不得写：

- 空间站位备忘全文。
- 整场戏概述。
- 集数或场景开始、结束等元信息。
- 创作意图。
- 剪辑说明。
- 新剧情动作。
- 未来剧情。
- 可见画面正文。
- 字幕。
- 观众说明。
- 角色不知道的信息。
- 剧本未发生的信息。

语言：

- 优先使用简短英文。
- 如项目明确要求中文，可使用中文。
- 无论语言如何，都不得作为画面生成内容。
- 通常只写一句简短连续性。

## 11. 编号镜头与时间长度检查规则

每个镜头必须使用编号结构：

```text
镜头一
时间长度：...秒
景别：...
构图：...
机位运动：...
画面内容：...
台词：...
```

字段规则：

- `时间长度` 使用整数秒。
- `景别` 写清主要景别。
- `构图` 只简述主体画面关系，不写过重细节。
- `机位运动` 只写短句，保留运动方式和必要情绪目的。
- `画面内容` 每镜最多 2 句，优先写可见动作、表情、道具变化和空间关系。
- `台词` 独立填写；无台词写 `台词：无`。
- 删除“意识到、仿佛、像是、见证、保持判断”等解释性词，改成眼神、呼吸、手、身体位置等可见表现。

检查项：

- 是否使用 `镜头一`、`镜头二` 这类编号。
- 每镜是否只有一个主要视觉任务。
- 主要运镜是否与当前剧情和情绪能量匹配；对白、关系拉扯和内心戏不得无触发升级为追逐或撞击级运镜。
- 追逐、逃跑、搏斗或突然危险出现时，运镜升级是否有明确剧情触发。
- 暧昧、亲密距离缩短或关系拉扯场景如使用浅景深，是否仍保证必要面部、手部、听戏反应、出口、站位和关键道具连续性可读。
- 每镜是否有 `时间长度：X秒`。
- 秒数是否为整数。
- 各镜头时间长度相加是否等于标题行总时长。
- 每镜时长是否足够完成台词、动作和情绪停顿。
- 台词自然说完是否优先于镜头数量。
- 是否先用台词密度反推时长，确认本段台词、停顿和反应能在当前时长内自然完成。
- 动作自然完成是否优先于炫技运镜。
- 情绪停顿是否有余味。
- 是否没有为了凑满 15 秒而新增无信息镜头、重复说明或后续剧情。
- 如果实际时长短于 15 秒，标题行是否按实际总时长结束。

如 15 秒容量不足以容纳原文台词、动作或必要停顿，应切新段，不得压缩、改写、合并台词；如原文容量自然短于 15 秒，不得为拉满时长新增无信息镜头。

删除、合并或插入镜头后，必须重新执行镜头编号、总时长、台词覆盖、动作因果和前后空间连续性检查。

## 12. 台词保真自检

输出前检查：

- 是否已定位剧本原文。
- 每句台词是否逐字复制。
- 是否保留原语言。
- 是否保留原词序。
- 是否保留原标点。
- 是否保留原大小写。
- 是否保留原语气词。
- 是否保留原中英混排。
- 是否保留原角色名和称谓。
- 是否用「」包裹。
- 是否没有翻译、改写、删减、合并、补写、润色、意译。
- 是否没有为了适配镜头而改变台词。
- 是否没有把后文台词提前放入当前小段。
- 是否没有凭记忆补写台词。
- 是否没有让角色在不可能的时间内完成多句台词、停顿和反应。
- 每个源台词实例是否在对应剧情位置完整出现一次。
- 是否没有遗漏、重复或跨镜拆分造成的重复台词。

无法定位原文台词时，不得生成该台词。

---

## 13. OS / VO / 画外音自检

检查项：

- 是否区分 `内心OS`、`内心独白`、`心声` 与普通 `OS`、`画外音`、`OV`、`VO`。
- 是否依据剧本或项目规则判断声音来源。
- 明确标注的 `V.O.` / `VO` 是否默认注明“不动嘴”，除非剧本或项目规则明确要求画面角色同步说话。
- 项目规定 `OS = 内心OS，不说台词，不动嘴` 时，是否严格执行。
- 无法判断声音来源时，是否保留原标注并避免擅自让画面角色开口。
- 内心声音是否标注“不说台词，不动嘴”。
- 画面角色是否嘴唇闭合、不张嘴、不对口型。
- 所有声音内容是否仍逐字复制原文。
- 是否没有把旁白改成角色口播。
- 是否没有把画外音误写成画面字幕。

如果剧本出现石板、屏幕、书页、碑文或类似可见文字载体，除非用户或项目明确要求可读文字，否则不要在 AI 视频 Prompt 中强行生成具体可读文字；可转写为模糊符号、文字状光痕、发光纹路、光点排列或不可辨识书写痕迹。固定控制行为“不制作字幕”时，不得把这些内容处理成字幕。

---

## 14. 空间连续性自检

检查项：

- 本段空间站位备忘是否明确。
- 每条镜头是否继承上一镜位置。
- 是否区分物理空间左右、画面构图左右和人物自身左右。
- 摄影机换位或反打是否只改变画面左右，没有无故改变人物物理位置。
- 前后景关系是否连续。
- 面对方向是否连续。
- 人物与门、窗、桌、床、墙角、车辆、王座等锚点关系是否连续。
- 角色位置变化是否写出移动过程。
- 人物移动是否能从上一位置实际到达下一位置。
- 前后景遮挡是否与当前摄影机位置一致。
- 对话视线是否清楚。
- 权力关系变化是否通过前后景、距离、遮挡或镜头高度体现。
- 是否没有无故跳位。
- 每个小段结束后是否更新内部场景状态，并作为下一段起始条件。
- 用户修正的连续性是否已传播到有效范围内所有受影响内容，并在明确状态变化或场景结束后停止继承。

---

## 15. 道具连续性自检

检查项：

- 道具是否来自剧本或项目资料。
- 是否没有编造关键道具。
- 每个入栏道具是否发生实际交互、控制权变化、位置变化、状态或生命周期变化，或为当前生成所必需的连续性锚点。
- 是否没有把未发生交互或变化的稳定人物资产、普通背景陈设重复列为关键道具。
- 关键道具是否写明位置。
- 关键道具是否写明持有者。
- 道具状态是否连续。
- 道具生命周期变化是否有剧本或项目资料支持。
- 道具位移是否在镜头正文中写出过程。
- 道具是否没有凭空出现。
- 道具是否没有凭空消失。
- 道具状态是否与后续既定动作兼容；如果当前状态会阻碍后续动作，是否已写明有依据的状态变化，或删除无依据的推断。
- 道具语言是否中文为主，必要时中英双语。
- 是否没有无故纯英文。
- 如果没有关键道具，是否写明“无关键道具”。

---

## 16. 摄影几何自检

检查项：

- 摄影机高度、俯仰角度、主体位置、主体运动方向和摄影机运动方向是否互相成立。
- 前景与后景关系是否符合摄影机位置。
- 跟随、迎拍、接近或远离关系是否清楚且物理一致。
- 主体是否被同时描述为接近和远离同一摄影机。
- 摄影机高度与俯拍、平拍或仰拍描述是否具有可成立的空间关系。
- 主体、位置、动作或光源是否写明方向和可见结果，避免将光线、门框、阴影、火焰或镜面写成主动行动者，或使用可能被误解为燃烧、穿透、缠绕、切割、物体主动运动的文学比喻。
- 镜面、玻璃或反射是否仅在剧情或视觉任务必要时使用，且保持单一反射面、简单静止的空间关系；关键身份、动作方向、人物交互和连续性结果是否没有只依赖反射表达。

## 17. 最终交付质量标准

合格输出应满足：

- 剧本原文可追溯。
- 当前处理范围准确。
- 每段生成前已对齐范围、场景、时长、镜头数、台词、Context Lock、光线、道具和角色状态。
- 台词逐字保真。
- 每个源台词实例完整覆盖一次，没有遗漏、重复或改写。
- OS / VO / 画外音处理符合剧本或项目规则。
- 角色状态、声音与镜头表演职责清楚：状态栏不堆具体表演，声音栏不写纯心理解释，具体表演落在对应镜头。
- 15 秒或实际短时长容量明确。
- 每镜时间长度完整，整数秒相加等于标题行总时长。
- 输出外壳完整。
- 顶层字段保持闭合；未确认项目扩展时没有新增、改名、删除或重排，已明确确认的项目级扩展字段被保留。
- 场景、角色、空间、道具、Context Lock 完整。
- 场景氛围只写可视物理环境，未混入人物语气、心理、关系判断或剧情评价；时间字段只保留按项目词表标准化的可见时间状态。
- 道具栏只保留发生交互、变化或必要连续性的物件；角色状态栏未机械重复稳定角色资产。
- 画幅遵守项目要求。
- 视觉风格承接项目设定。
- 视觉基调符合当前场景，没有机械继承上一段不适用的光线、天气或特殊效果。
- 默认不写 palette / 色号，除非用户明确要求。
- 整体视频采用控制在 1 行、最多 3 个风格点。
- 角色站位连续。
- 物理空间左右、画面构图左右和人物自身左右没有混淆。
- 镜头有时间长度、景别、简洁构图、机位运动、画面内容和台词字段。
- 每个镜头只有一个主要视觉任务。
- 心理原因先于由其触发的动作结果。
- 摄影机位置、角度和运动符合物理关系。
- 信息进入正确字段，没有无生成价值的元信息或机械重复。
- 情绪通过眼神、呼吸、嘴唇、下颌、手部、肩线、重心等可见细节表达。
- 台词语义、停顿和语气转折已转化为表演节奏，没有把标点本身写成表演时间点。
- 无台词角色有听戏反应。
- 无台词角色没有被写成开口或对口型状态。
- 动作戏有节拍。
- 对话戏有视线关系。
- 悬疑戏不提前揭示真相。
- 权力关系通过空间和前后景体现。
- 不出现固定项目风格误套。
- 不出现占位语。
- 不出现无故英文道具栏。
- 不出现机械负面词堆叠。
- 不出现 YAML、allowed-tools 或 Skill 工具声明。
- 不生成 Project 初始化助手、Project Instructions 模板、启动资料收集模板或测试用例。
- 镜头字段不被色号、画幅标签、流程词或制作说明污染。
- 表演描述和 `画面内容` 中的负面约束具有明确纠错价值，未机械强调正常状态；“无 Logo、无水印”等技术交付约束未被误套用 G02。
- 描述字面且物理因果清楚，反射与浅景深没有遮蔽关键连续性信息。
- 不使用旧版 `△0.0-3.0s` 绝对起止时间轴格式。
