# AI视频分镜Prompt转换器_禁止继承与反污染规则

## 0. 文件用途

本文件只用于跨项目污染、旧格式回退、样例泄漏、历史来源继承以及 Skill 维护／合并的专项审查，不是普通生产任务的默认 reference。

普通生产必需规则必须在以下权威来源中独立成立：

- `SKILL.md`：职责、材料闸门、条件路由和项目内容不得写入 Skill。
- `main-converter-rules.md`：范围、优先级、原文／台词、容量和项目级配置边界。
- `camera-performance-rules.md`：镜头、表演、站位、稳定性和摄影几何。
- `output-format-qa.md`：精确外壳、字段职责、时长、Context Lock 和交付 QA。

本文件中的重复表述是污染 canary 和专项检查项，不得覆盖上述权威来源，也不得成为普通生产核心合同的唯一来源。本文件不要求读取任何历史源文件、旧版规则文件或开发阶段解析报告，不作为用户可见输出模板。

---

## 1. 禁止继承 YAML / allowed-tools / 工具环境声明

不得把历史源文件中的 YAML 元数据、工具配置字段、工具权限声明、运行环境声明或模型能力声明，当成 主转换规则 的执行规则。

禁止继承或输出：

- YAML 头部。
- `name:`、`version:`、`description:` 等元数据字段。
- `allowed-tools:` 等工具配置字段。
- 工具权限声明。
- 运行环境声明。
- 模型能力声明。
- 任何看起来像系统工具配置的内容。

原因：

- 这些属于历史源文件、工具环境或运行声明，不属于分镜转换器的自然语言执行规则。
- 直接继承会造成虚假工具能力、格式污染和执行边界混乱。

正确处理：

- 只提炼可执行的规则含义。
- 不复制工具声明。
- 不暗示 skill 拥有未提供的固定工具能力。
- 历史源文件可能存在 Skill 运行声明，不得照抄。

---

## 2. 禁止替换最终前情字段

如历史来源使用其他前情字段名，例如 `The preceding plot`，最终仍以 `[Context Lock - Do Not Render]` 为准。

最终前情字段必须是：

`[Context Lock - Do Not Render]: ...`

该字段只用于锁定连续性：

- 只记录当前小段起始所需的人物位置与姿态、影响当前画面的相对关系、关键道具状态和上一段尚未结束的动作状态。
- 不概括整场戏。
- 不加入新剧情动作。
- 不写未来剧情。
- 不作为画面内容。
- 不生成字幕。

---

## 3. 禁止继承默认画幅

不得从任何历史规则源、参考文件或客户样例中继承默认画幅。

画幅比例必须以以下来源为准：

1. 用户当前要求。
2. Project Instructions。
3. 启动资料表。
4. 客户补充规则。
5. 当前项目资料。

如果项目明确为 9:16，则按竖屏构图执行。  
如果项目明确为 16:9、21:9、1:1 或其他比例，则按项目要求执行。  
不得在已明确 9:16 的项目中套用横屏构图规则。  
不得把任何历史来源中的默认画幅写成本 skill 的默认画幅。

---

## 4. 禁止继承旧时间格式和“不写时长”的输出习惯

不得从任何历史规则源或参考文件中继承“不写时长”的输出习惯。

本 skill 面向 AI 视频约 15 秒小段生成，每个编号镜头必须有整数秒时间长度。

本 skill 必须：

- 使用 `镜头一`、`镜头二` 这类编号镜头。
- 每个镜头有 `时间长度：X秒`。
- 秒数使用整数。
- 每段默认总时长约 15 秒，或按用户指定时长、自然完成时长结束。
- 各镜头时间长度相加必须等于标题行总时长。

不得回退到旧版 `△0.0-3.0s` 绝对起止时间轴格式。时间长度是容量控制、台词节奏、动作节拍和镜头切分的核心工具。

---

## 5. 禁止破坏闭合的核心输出外壳

正式输出外壳是闭合的顶层字段集合。除非用户当前要求或项目规范明确增加项目级字段，否则不得新增、改名、删除或重排顶层字段。项目明确增加的字段不视为格式污染。时长由标题总时长和各编号镜头的整数秒表达，不得临时新增 `【时长约束】` 等顶层字段。

不得删除或弱化以下字段：

- 标题行。
- `【约束铁律】：仅制作音效，不制作音乐，不制作字幕`。
- `整体视频采用`。
- `场景设定`。
- `角色`。
- `空间站位备忘`。
- `道具设定`。
- `[Context Lock - Do Not Render]`。
- 编号镜头与每镜时间长度。

不得把输出简化成只有镜头正文。  
不得把角色、空间、道具、Context Lock 合并成一段模糊说明。  
不得用参考资料中的旧格式替代本 skill 的输出外壳。

---

## 6. 禁止把具体项目风格写成通用规则

不得把任何具体项目的视觉风格写成所有项目默认。

禁止固定继承的内容包括：

- 某个客户项目的世界观风格。
- 某个客户样例中的视觉风格。
- 某个神话、科幻、悬疑、广告项目的专属风格。
- 单次任务里的画面氛围。
- 单场景或单小段的临时风格。

处理原则：

- 具体项目风格只用于该项目。
- 新项目必须读取当前项目资料。
- 没有项目风格时，不得套用其他项目风格。
- 不得因为参考材料出现某个风格，就把它写成默认视觉风格。

---

## 7. 禁止把固定色号、palette 或摄影设备写成所有项目默认

不得把某个项目的 palette、色号、摄影设备或镜头品牌写成通用默认。

禁止：

- 固定使用其他项目色号。
- 编造 palette。
- 把客户样例色号复制到无关项目。
- 默认逐段写入 palette 或色号。
- 固定使用某个摄影机、镜头品牌或镜头套装。
- 把客户样例摄影设备写成所有项目默认。

正确处理：

- 默认不在分镜 Prompt 中写 palette 或色号。
- 当前项目提供色号时，也不自动逐段写入，除非用户明确要求严格保留。
- 当前项目只提供风格倾向时，只写风格倾向。
- 摄影设备和镜头品牌是项目级约束，不是全局默认字段。

---

## 8. 禁止保留占位语

最终分镜输出不得保留占位语，包括但不限于：

- 根据剧情分配。
- 待补充。
- 未提供。
- 视情况而定。
- 按项目而定。
- 可能是。
- 大概。
- TBD。
- XXX。
- 某角色。
- 某地点。
- 某道具。

例外：

- 在说明禁止项或规则时，可以提及这些词。
- 在正式分镜输出字段中不得保留这些词。

无法确认的信息，不得用占位语糊弄，应说明无法定位或缺少资料。

---

## 9. 禁止道具栏无故纯英文

道具设定默认中文为主。

不得无故将道具栏全部写成英文。

允许中英双语：

`中文道具名 / English visual keyword`

适用场景：

- 需要增强 AI 视频模型识别。
- 项目本身要求英文关键词。
- 道具为国际通用视觉对象。
- 用户明确要求英文 Prompt。

不得：

- 把中文项目的道具栏全部改成英文。
- 翻译客户要求保留原名的专有道具。
- 因模型偏好而牺牲项目命名一致性。
- 为了填充道具栏编造道具。

如果本段没有关键道具，应写：

`道具设定：无关键道具。`

---

## 10. 禁止把 Project 初始化助手规则混入分镜转换器

本 skill 的默认生产任务是分镜 Prompt 转换。

涉及规则文件、模板、初始化助手等非分镜任务时，不应混入分镜输出流程；除非用户明确要求规则维护，否则不主动生成这些内容。

当用户要求分镜时，不得输出：

- Project 启动提问流程。
- 启动资料收集表。
- 客户资料采集问卷。
- Project 初始化步骤。
- 项目文件结构规划。
- 母版 Project 使用说明。
- 后续协作流程设计。
- 项目迁移摘要模板。

不得把其他 Project 工具的规则混入本分镜转换器。

---

## 11. 禁止把 Project Instructions 模板混入 主转换规则

本 skill 主规则 不是 Project Instructions 模板。

不得输出：

- 某项目的 Project Instructions 填写版。
- Project Instructions 字段模板。
- 启动资料表模板。
- 项目级长期规则模板。
- 客户确认问题模板。
- 母版规则选择表。
- 具体 Project 初始化流程。

本 skill 主规则 只规定分镜转换器如何工作。  
项目级规则应由具体 Project 文件提供，不应混入本 skill 的通用规则。

---

## 12. 禁止把客户样例剧情写成项目长期设定

客户样例、参考图、单次 Prompt、单段剧情，只能作为当前任务或当前项目资料参考。

不得把以下内容写成长期规则：

- 单集剧情。
- 单场剧情。
- 单小段临时状态。
- 单次客户样例的角色动作。
- 单张参考图的临时姿态。
- 某段 Prompt 中的具体道具。
- 某个客户样例中的视觉世界观。
- 某次测试内容。

处理原则：

- 项目长期设定必须来自 Project Instructions、启动资料表或用户明确确认。
- 不确定信息必须保持不确定，不得升级为项目长期规则。
- 单段剧情不能污染全局 Instructions。

---

## 13. 禁止把高密度表演规则机械写进每条镜头

演员表演控制规则是参考，不是每条镜头的机械填空表。

不得每条镜头都写满：

- 多个眼神锚点。
- 多个眉眼锚点。
- 多个嘴唇 / 下颌锚点。
- 多个呼吸锚点。
- 多个身体泄漏动作。
- 负面约束。
- 复杂潜台词分析。

`1+3+1+1` 只作为内部表演密度控制参考，不得机械写满。

正确处理：

- 根据景别选择表演密度。
- 特写写细。
- 中景写身体与关系。
- 全景写站位与空间压迫。
- 运动镜头复杂时，演员动作减半。
- 只选当前最有效的少数表演锚点。

---

## 14. 禁止每段机械加入长串负面约束

AIGC 假表演规避规则用于内部自检，不是每段必输出负面词清单。

不得每段机械输出：

- 不要瞪眼。
- 不要假笑。
- 不要大幅点头。
- 不要机械微笑。
- 不要表情清零。
- 不要假哭。
- 不要眼神乱飘。
- 不要舞台剧动作。
- 以及其他长串负面约束。

正确处理：

- 先通过正向镜头和表演描述规避问题。
- 必要时只写当前镜头最相关的 1–2 项限制。
- 不让负面词挤占主体动作、情绪和空间关系。

G02 只适用于表演描述和 `画面内容`。在该范围内，负面约束必须具有明确纠错价值：只保留能够阻止高概率生成错误、连续性错误或误表演的限制；对“未移动、未摘除、不提高音量”等正常情况下不必强调的状态，优先改写为正面的可见状态、需要发生的动作或声音表现。固定 `【约束铁律】：仅制作音效，不制作音乐，不制作字幕` 独立生效；“无 Logo、无水印”等技术交付约束不受 G02 限制，按当前项目要求处理。

---

## 15. 禁止说明词和项目规则机械污染镜头字段

镜头字段应直接呈现可见画面，不应被元叙述、流程说明、制作说明或项目规则标签污染。

减少在镜头字段中使用：

- 承接上一段。
- 本段。
- 随后。
- 准备。
- 见证。
- 未离开。
- 仍在。
- 不使用。
- 竖屏。
- 9:16。
- 色号。
- 摄影设备。
- 镜头品牌。

正确处理：

- 把说明词改成可见状态、站位、动作、道具位置、光影或表演细节。
- 道具连续性写成道具由谁持有、放在哪里、朝向哪里、是否移动。
- 项目已确定画幅后，按该画幅组织构图即可，不必每条镜头反复写画幅标签。
- `整体视频采用` 默认不写 palette / 色号；镜头字段只写可见色彩效果、材质和光影。
- 摄影设备或镜头品牌仅在用户或项目资料明确要求时作为项目规则使用，不作为通用必填字段。

## 16. 历史来源 / 当前 Instructions / 项目资料冲突时的处理原则

冲突优先级以 `main-converter-rules.md` 第 2 节为唯一权威来源。本节只检查历史来源、旧输出和样例没有绕过该优先级。

具体处理：

- 如果历史来源建议不写时长，但本 skill 要求每镜时间长度：执行每镜时间长度。
- 如果历史来源使用 `△0.0-3.0s` 绝对起止时间轴，但本 skill 要求编号镜头：执行编号镜头和整数秒时间长度。
- 如果历史来源使用其他前情字段，但本 skill 要求 `[Context Lock - Do Not Render]`：执行 `[Context Lock - Do Not Render]`。
- 如果历史来源有默认画幅，但当前项目明确画幅：执行当前项目画幅。
- 如果历史来源包含具体项目风格、色号、palette、摄影设备或镜头品牌，但当前项目未确认：不得套用。
- 如果参考规则库要求高密度表演增强，但当前镜头复杂：降低表演密度。
- reference 细则与主转换规则 冲突：执行主转换规则。
- 剧本原文与模型推断冲突：执行剧本原文。
- 用户当前指定处理范围与历史上下文冲突：执行当前用户指定范围。

## 17. 最终反污染自检

输出前内部检查：

- 是否没有 YAML 头部。
- 是否没有 allowed-tools。
- 是否没有工具环境声明。
- 是否没有用其他前情字段替代 `[Context Lock - Do Not Render]`。
- 是否没有继承默认画幅。
- 是否没有省略每镜时间长度。
- 是否没有回退到旧版 `△0.0-3.0s` 绝对起止时间轴格式。
- 是否没有删除标题、场景、角色、空间、道具、Context Lock 字段。
- 顶层字段是否保持闭合；未获明确项目扩展时，是否没有新增、改名、删除或重排；时长是否仍只由标题和编号镜头时长表达。
- 是否没有把其他项目的风格、色号、palette、摄影设备或镜头品牌写成通用默认。
- 是否没有保留占位语。
- 是否没有道具栏无故纯英文。
- 是否没有混入 Project 初始化助手。
- 是否没有混入 Project Instructions 模板。
- 是否没有把客户样例剧情升级为长期设定。
- 是否没有把表演锚点机械堆满每条镜头。
- 是否没有每段机械加入长串负面约束。
- 表演描述和 `画面内容` 中的负面约束是否具有纠错价值，且没有机械强调正常状态；技术交付约束是否没有被误套用 G02。
- 是否没有把说明词、画幅标签、色号、摄影设备或镜头品牌机械写进镜头字段。
- 是否没有超出用户当前指定处理范围。
