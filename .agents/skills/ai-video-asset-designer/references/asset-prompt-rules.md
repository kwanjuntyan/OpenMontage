# 资产图 Prompt 规则

## 设计范围

Prompt 只描述“可复用资产图”本身，不写成 15 秒视频分镜或运动提示。可以包含姿态、视角、构图和状态，用于建立一致性参考；不要添加镜头运动、时间轴、对白、音效、转场或视频生成参数。

默认采用“平台中立母版 Prompt + 按需模型适配版”：

- 母版保留叙事事实、视觉锚点、参考图角色、构图目标、材质/光线和硬约束。
- 适配版只调整模型需要的语言组织、参数提示或参考图说明，不改变资产事实。

## 母版字段顺序

每项资产按以下顺序组织，缺少的字段不要编造：

1. Asset identity：internal_key、中文 asset_id、类别、基准/变体和出现范围。
2. Scene / background：环境、时间、天气、背景关系和画布用途。
3. Subject：角色/道具/车辆/生物的外观锚点、比例、结构和状态。
4. Details / materials：服装、妆发、材质、纹理、磨损、颜色与关键标记。
5. Views / composition：正面/侧面/背面、三视图、细节插图、白底或情境板，以及构图顺序。
6. References：每张参考图的 role 与“参考什么/不参考什么”。
7. Continuity constraints：必须保持、允许变化、禁止新增、文字准确性和透明度要求。
8. Output intent：供何种视频/分镜工作流复用、是否需要透明背景或分层留白。

把高影响约束写成可验证的正向句子，例如“保留左眉上方细小斜痕，位于右侧画面时仍在角色左眉”；避免只写“不要变化”。

## 资产类型模板

- 角色：全身基准 + 正/侧/背面 + 面部/服装细节；锁定年龄阶段、体型、发型、脸部比例、标志性服装和状态变体。
- 场景：建立空间结构、入口/出口、地标、材质、光向和色彩；日/夜、天气、破坏阶段分开时明确差异。
- 道具：给出轮廓、尺度参照、材料、关键结构、刻痕/文字、开合或破损状态；叙事文字有不确定性时先阻塞。
- 车辆/生物：正侧后视图、关键机械/生理结构、尺度、运动痕迹或损伤状态；不把视频运动写入图像 Prompt。
- 图形/UI：说明画布、网格、排版层级、文字内容和字形禁区；模型无法保证精确文字时把风险交给后期或标记待确认。
- 风格基准：把时代/地域、真实度、色彩范围、光线方式、材质系统、空气感和画面密度写成可见规则；不要只写“高级、电影感、梦幻、震撼”等抽象词，也不要用风格图替代具体资产图。

## 参考图规则

参考图可以承担 identity、face_or_age、hair、costume、pose、environment_space、prop_shape、style、material、lighting、color、composition、mood 或 correction 等职责。Prompt 必须明确组合关系：

- identity：保持人物/道具识别特征，不借用其背景或风格。
- face_or_age / hair / costume / pose：只继承被指定的人物维度，不把同一参考图的其他人物特征自动带入。
- environment_space / prop_shape：分别锁定空间结构或道具主体造型，不借用无关人物和装饰。
- style：借用绘制/摄影/渲染语言，不改变剧本设定。
- material：借用纹理、表面反射或颜色，不改变轮廓。
- lighting / color / mood：只约束光线、色彩或情绪气氛，不改变资产身份和结构。
- composition：借用布局、视角或留白，不借用其中的主体身份。
- correction：以已有生成结果为基础，指出必须保留和仅需修正的内容。

每张参考图都要写“参考什么、不参考什么”。存在多张图时必须写 reference_priority，例如“身份与主体结构 ＞ 服装材质 ＞ 场景光线 ＞ 氛围细节”。如果参考职责会影响模型生成，职责和优先级必须出现在同一可复制 Prompt 代码块中；仅供用户确认的说明可以放在代码块外。

若没有本地参考图，写“无外部参考图；依据项目资料库锚点设计”，不要伪造图片链接。

## 信息密度与拆分

一条 Prompt 只解决一个清晰的资产生产目标。复杂资产信息过多时，按实际生产需要拆分：

- 角色：基础主设定、多角度、表情/状态、服装细节；
- 场景：整体空间、局部区域、日夜/天气状态、材质细节；
- 道具/特殊资产：整体造型、结构细节、使用状态、损坏状态；
- 风格资产：整体风格、色彩光线、材质质感。

拆分后仍沿用同一基准资产键，通过变体或 Prompt 版本表达差异。不要为了“完整”把互相干扰的身份、状态、构图和多个任务塞入一条过长 Prompt。

## 画幅与可读文字

只有用户明确要求、项目风格规则已确认固定画幅，或当前资产生产确实需要指定比例时，才写画幅/宽高比；否则不默认添加。透明背景、分层留白也只在用途明确时写入。

需要可读文字时，逐字记录授权文字、位置、大小关系、方向和清晰度要求；不需要文字时不额外增加文字要求。关键文字未确认或模型无法可靠保证时，标记 needs_confirmation 或交给后期排版，不自行发明。

## 批次与代码块

- 规划确认后每轮最多输出 5 项，按生产清单中的批次顺序。
- 每项使用一个独立的可复制代码块，代码块内只放可提交给图像模型的 Prompt 正文，不混入解释、来源或 Markdown 标题。
- 代码块外提供 prompt_id、模型版本、参考图角色、来源/状态和简短 QA 说明。
- prompt_id 形如 A0002-P01；同一资产修订递增 P02，不得重用旧 Prompt 编号。
- 中英文均可；默认使用项目工作语言（通常为中文），必要的模型 API 字段置于代码块外。

## 约束与安全

必须保留的内容放在约束段末尾并再次复述。明确“保留 / 允许变化 / 禁止新增”。不使用空泛的“高质量、电影感”替代具体视觉事实。避免无授权的真人肖像复制、品牌仿制、版权角色或敏感个人资料；遇到此类要求先请求授权或改为抽象化设计。

不要因为模型偏好而增加镜头、动作、对白、故事情节、未确认的伤痕或装饰。若资料冲突或核心字段未知，Prompt 状态为 blocked 或 needs_confirmation，不要用看似完整的文字掩盖缺口。

## 修订与诊断

用户提供生成结果或失败描述后，按“事实偏差、身份漂移、结构/材质错误、构图不符、文本错误、模型适配问题”分类诊断。只修改导致问题的字段，并保留未变约束；每次修订产生新的 prompt_id，在生产清单中记录原因。

定向修改 Prompt 必须说明基础图、保持项、只修改项和最终目标。用户要求局部修改时，默认保留原图构图、视角、主体位置、光线方向、已确认身份和叙事信息，除非这些内容正是本轮修改目标。除非用户明确要求，不在本 Skill 内直接调用图像生成。
