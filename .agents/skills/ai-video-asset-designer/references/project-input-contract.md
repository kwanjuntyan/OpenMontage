# 项目输入契约

## 目的

ai-video-asset-designer 是项目资料库初始化后的下游 Skill。它把已定位的剧本、客户资料和项目上下文转换为“需要设计哪些视觉资产、每项资产如何生产”的可审阅结果。它不负责建立或修订项目资料库，也不把资产设计结论写回上游资料库。

调用入口是 $ai-video-project-context 已完成初次初始化后的项目根目录。若上下文尚未初始化、来源不可定位或权限范围不清，先暂停资产设计并要求补齐输入。

## 输入优先级

按以下优先级读取事实；越靠前的来源越能约束设计：

1. 用户本轮明确给出的项目要求，以及带来源、确认人/确认轮次的客户修改或项目级已确认决策。
2. 项目根目录内的原始剧本、客户交付资料和已授权视觉参考；已被更高优先级确认决策明确替代的旧事实除外。
3. $ai-video-project-context 生成的项目简报、人物设定、世界观词典、分集场景索引、风格规则和连续性记录。它们主要用于导航；其中带明确确认依据的字段按其原始确认来源处理。
4. 本 Skill 的规则与模型适配器。
5. 仅用于填补低风险视觉空缺的设计提案。

上游摘要是导航和索引，不替代原始剧本或客户资料中的逐字事实，也不能凭“更新较新”自动覆盖来源。涉及角色身份、叙事状态、品牌元素、时代、版权素材或连续性冲突时，回到原始来源或确认记录核对并记录位置。确认决策替代旧事实时，必须记录被替代来源和确认依据，不能把它当作普通摘要冲突。

## 标准项目上下文输入

按上游 ai-video-project-context 的中文主文件名契约探测项目资料库。下表中的语义角色比文件名更重要：

| 语义角色 | 中文主文件名（优先） | 英文兼容文件名（仅旧项目） |
| --- | --- | --- |
| project_brief | 项目简报.md | project-brief.md |
| script_overview | 剧本总览.md | script-overview.md |
| character_bible | 人物设定.md | character-bible.md |
| worldbuilding_glossary | 世界观词典.md | worldbuilding-glossary.md |
| episode_scene_index | 分集场景索引.md | episode-scene-index.md |
| style_rules | 风格规则.md | style-rules.md |
| continuity_notes | 连续性记录.md | continuity-notes.md |

source/ 或上游声明的原始资料目录继续作为剧本和客户材料入口；其名称不因上下文资料文件改为中文而自动改变。

文件探测与兼容规则：

1. 中文主文件名存在时优先读取，并在来源记录中保留实际中文路径。
2. 中文主文件名不存在、英文兼容文件存在时，读取英文文件；将其标记为 legacy_english，不创建中文副本。
3. 同一语义角色的中文和英文文件同时存在时，不自动合并、覆盖或选择一方；报告 duplicate_context_conflict，并要求用户确认权威文件。
4. 不因缺少可选角色文件而阻塞；缺少项目范围、来源定位或与待设计资产直接相关的核心事实则标记为 needs_confirmation 或 blocked。
5. 不依赖文件名猜测内容。读取文件后确认标题/章节语义与角色匹配，并保持原始名称、大小写和混合语言术语。

资产规划和生产清单的 source_refs 必须记录本次实际读取的文件名（中文主文件名或英文兼容文件名）、集/场/段落/页码定位和来源层。不要把文件名变换成另一套别名。

## 事实分层

每一个资产字段和 Prompt 约束都标注下列来源层：

| 层级 | 含义 | 处理方式 |
| --- | --- | --- |
| source_fact | 原始剧本/客户资料可定位的事实 | 保留来源位置；不得静默改写 |
| confirmed_design | 用户或项目资料已确认的视觉设计 | 可直接进入资产规划和 Prompt |
| visual_design_proposal | 为补齐低风险空缺提出的方案 | 显式标注“待确认”；不得伪装成事实 |
| unknown | 当前资料没有足够依据 | 不编造，必要时列入确认问题 |
| conflict | 两个授权来源不一致 | 暂停受影响资产；列出冲突位置和决策点 |

设计提案可以补充材质、色调、构图偏好等低风险细节，但不能自行决定年龄、身份、品牌标识、关键道具功能、时代科技或会改变叙事的伤痕/变装。

## 授权路径与读取边界

1. 先确定项目根目录和本轮授权的文件/目录；不得通过模糊搜索读取工作区外的客户资料。
2. 只读取完成当前资产规划所需的最小来源集合；引用绝对路径时在内部记录，面向用户可用相对项目路径和章节/场景定位。
3. 不读取或依赖当前 11-Skill 运行时状态、旧版目录、其他项目缓存或已安装运行副本。
4. 不把原始剧本、客户资料或整段 Prompt 上传给外部服务。未来若接入 API，必须另行获得授权并通过脱敏/最小化检查。

## 写入边界

默认仅允许在当前项目根目录的 visual-assets/ 下创建或更新：

- 资产规划.md：资产目录、优先级、来源、变体、状态、确认记录。
- 资产生产清单.md：待生产队列、Prompt 编号、参考图角色、模型适配状态和 QA 状态。

完整生产 Prompt 只在对话中显示，每个 Prompt 放入可一键复制的独立代码块；除非用户明确要求，不写入 Markdown、日志、缓存或项目上下文文件。若目标目录已有文件，先读取并增量更新，不覆盖用户手工记录。

## 初始化判定与失败处理

- ready：能定位项目范围、风格规则、至少一份原始来源，并能为当前任务建立来源链。
- needs_confirmation：低风险字段可继续规划，但有待确认的视觉提案、批次范围或模型选择。
- blocked：核心事实缺失、来源冲突、授权不清、品牌/版权限制未决，或用户要求超出本 Skill 边界。

输出判定应同时说明：已读取哪些文件、哪些资产被纳入、哪些结论来自提案、下一步需要用户确认什么。不要用“资料库已初始化”替代实际来源定位。
