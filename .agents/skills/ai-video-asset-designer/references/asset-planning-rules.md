# 资产规划规则

## 规划目标

资产规划回答两个问题：

1. 为保持人物、场景和道具跨镜头一致，需要先设计哪些可复用视觉资产？
2. 每项资产当前是否可生产、需要哪些参考资料，以及生产后如何回收为可复用资产？

规划先覆盖复用价值和连续性风险，再覆盖装饰性细节。不要把一次性镜头描述直接当成可复用资产。

## 资产类别

至少检查以下类别，按项目实际需要取用：

- character：角色正反面、年龄/阶段、服装、妆发、伤痕、湿身、变装等状态变体。
- environment：可反复出现的地点、室内/室外、日/夜、天气或破坏阶段。
- prop：具有叙事功能、反复出现或必须保持形状的道具及状态变化。
- vehicle_or_creature：车辆、机械、动物、幻想生物及其结构/损伤状态。
- graphic_or_ui：徽记、包装、屏幕、地图、标识等平面视觉资产；要特别标记文字准确性风险。
- costume_or_set：在多个角色/场景间复用的服装套装或陈设组合。
- style_asset：用于统一时代、地域、科技层级、色彩、光线、材质、真实度和画面密度的风格基准；它不能替代具体角色、场景或道具资产。

## 正式资产、文字设定与临时元素

不要把所有可见元素都送入图片生产。每项候选元素必须得到 production_need：

- image_reference：需要单独生产资产图，用于多镜头一致性、客户确认、复杂结构或高风险生成。
- text_only：需要保留稳定文字设定，但简单描述已足以支撑后续制作。
- inline_temporary：仅在单个镜头出现、叙事影响低、跨镜头一致性要求低，可由后续镜头 Prompt 临时描述。
- undecided：资料或确认不足，暂不进入 Prompt 队列。

主角、重要配角、核心地点、关键道具、复杂生物/机械、品牌或产品对象、需要特写的资产，以及后续会作为参考图输入的资产，通常选择 image_reference。一次性普通背景物、远景人群、氛围杂物和简单非关键物件通常选择 inline_temporary。

临时元素如果在下游生成中反复出错、开始跨镜头复用或影响剧情理解，应提升为正式资产并重新分配优先级；不要继续依赖临时描述。

## 资产粒度与变体

一个“基准资产”应能在至少两个镜头、场景或集数中复用，或承载高连续性风险。以下变化通常建立变体，而不是覆盖基准资产：

- 日/夜、室内/室外、天气、季节或破坏阶段；
- 角色出现集数范围、年龄阶段、妆发/服装、颈部受伤、湿身、变装；
- 道具完好、破损、沾血、开启/关闭、缺件等剧情状态。

变体必须关联一个稳定的基准 internal_key，且写明“新增/更新/停用”关系。单纯改变镜头角度、景别或动作通常不新建资产，除非用户要求独立参考图。

## 优先级与队列

使用 P0、P1、P2：

- P0：主角/核心配角基准、核心地点、关键道具，或会造成多场戏返工的资产；优先生产。
- P1：高频复用、重要变体、主要车辆/生物、关键图形资产。
- P2：低频或局部装饰、可由镜头 Prompt 临时描述的资产。

同一批默认最多 5 个资产。按 P0 → P1 → P2 排序；同优先级综合出现频次、近景/特写需求、连续性风险、叙事作用、客户确认需求、生成难度、来源完整度和对下游返工的影响排序。超过 5 个时只展示下一批，其余保留在清单中。

## ID 与命名

内部键一经建立不可改名，格式为 A 加四位数字（如 A0001）。人类可读的 asset_id 使用中文、在项目内保持唯一并保持稳定：

- 场景：场景名_日、场景名_夜，必要时再加天气/破坏状态。
- 角色：角色名_EP08-10，有状态时追加 _颈部受伤、_湿身、_变装 等。
- 道具：道具名，有状态变化时追加 _破损、_开启 等。
- 其他类别：使用项目内通用名加最小必要的时间/状态后缀。

文件名使用中文不会影响 Markdown 或本地读取，但跨平台脚本、URL、第三方 API 和团队协作可能遇到编码/转义问题。因此仓库内部允许中文显示名；机器索引、JSON 字段和 Prompt 编号必须使用 ASCII 的 internal_key / prompt_id。不要以文件名代替稳定键。

## 来源与字段

每项资产至少记录：

| 字段 | 要求 |
| --- | --- |
| internal_key | 稳定、唯一、不可复用 |
| asset_id | 面向人的中文 ID |
| type | 资产类别 |
| priority | P0/P1/P2 |
| base_or_variant | base 或 variant；变体注明基准键 |
| narrative_or_visual_function | 叙事作用、客户确认用途或画面作用 |
| production_need | image_reference、text_only、inline_temporary 或 undecided |
| appearance_scope | 集数、场景、日/夜和状态范围 |
| source_refs | 文件相对路径 + 集/场/段落/页码定位 |
| source_layer | 事实分层值 |
| visual_anchor | 必须锁定的外观锚点 |
| required_views_or_states | 需要生产的视图、姿态、表情、光线或状态；没有则写“无” |
| reference_inputs | 每张参考图的职责、可继承内容、不可继承内容和优先级 |
| continuity_links | 角色—角色、角色—场景、角色—道具、场景—场景或风格—资产关系 |
| approval_required | 是否需要用户/客户确认，以及确认范围 |
| open_questions | 未决问题；没有则写“无” |
| status | planned、needs_confirmation、ready_for_prompt、prompted、produced、needs_revision、blocked |

参考图至少从以下职责中选择：identity、face_or_age、hair、costume、pose、environment_space、prop_shape、style、material、lighting、color、composition、mood、correction。每张图必须写“参考什么、不参考什么”；多张图存在时还要写 reference_priority，避免风格、姿态或背景污染身份和结构。

## 项目文件结构

visual-assets/资产规划.md 至少包含：

1. 本轮范围、授权来源和实际读取路径；
2. 规划摘要与项目级风格基准；
3. 正式资产及其 production_need、优先级、设定图需求和状态；
4. inline_temporary 元素及其临时处理原因；
5. 参考图职责、可继承/不可继承内容和优先级；
6. 资产一致性关系、冲突、风险和待确认事项；
7. 增量修改记录，不删除仍有效的旧决策。

visual-assets/资产生产清单.md 至少包含 batch_id、internal_key、asset_id、production_need、priority、required_views_or_states、prompt_id、adapter_target、reference_inputs、status、QA 结论和修订原因。只把 image_reference 或用户明确要求的项目排入 Prompt 批次；不保存完整 Prompt 正文。

客户审核项目应把“可给客户确认的资产结论”与“内部来源、风险、冲突和制作备注”分开呈现，避免把内部敏感信息混入客户可读摘要，也不能为了客户可读性删除内部追溯记录。品牌、产品、人物和关键物件的 approval_required 必须进入规划与生产清单。

## 轻量项目

单镜头测试、短广告或快速视觉验证可以使用简版规划，但仍必须判断：主要角色/场景是否需要一致、是否有核心道具、是否需要风格基准、哪些元素可以 inline_temporary，以及有哪些待确认风险。轻量不代表跳过来源、命名和确认边界。

## 规划流程

1. 读取项目输入契约，列出已授权来源和来源层。
2. 从场景索引和原始剧本提取出现频次、状态变化、跨集连续性和高风险图形。
3. 合并同一基准资产，拆出必要变体，分配稳定键和中文 asset_id。
4. 为每项资产写视觉锚点、production_need、required_views_or_states、参考图职责与优先级、连续性关系、来源定位、缺口和优先级。
5. 生成或增量更新当前项目 visual-assets/资产规划.md 与 visual-assets/资产生产清单.md。
6. 输出本轮拟展示的最多 5 项，并明确“先确认规划，后输出 Prompt”的门槛。
7. 仅在用户确认后进入 Prompt 设计；已确认的规划更新状态，不抹除旧的来源和决策记录。

## 冲突、提案与更新

- 关键设定冲突时，状态为 blocked，同时列出双方来源和需要用户裁决的问题。
- 低风险细节缺失时，可以写 visual_design_proposal，但必须在规划和 Prompt 中同时显示“待确认”。
- 用户确认提案后，将该字段改为 confirmed_design，保留确认日期/轮次和原提案。
- 不因一次 Prompt 修订而改变资产 ID；只有资产语义或状态边界改变时才新建变体。
- 生产清单记录 prompt_id、批次、模型适配版本、参考图角色、QA 状态和修订原因；完整 Prompt 仍只在对话中保留。
- 下游问题只涉及视觉稳定性时，局部更新资产或把临时元素升级为正式资产；如果反馈要求改变剧情事实、身份、关系或世界规则，移交 ai-video-project-context 核对来源，不在资产规划中改写 canon。

## 规划完成标准

规划可进入 Prompt 阶段，必须满足：基准/变体关系清楚；每项有可追溯来源或显式提案；production_need、所需视图/状态、优先级和批次明确；参考图职责与优先级清楚；关键连续性关系已记录；品牌/客户限制和确认范围已记录；高影响冲突已解决或阻塞；项目风格规则已纳入；用户知道哪些内容将写入 Markdown、哪些 Prompt 只显示在对话框中。
