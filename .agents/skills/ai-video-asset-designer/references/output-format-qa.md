# 输出格式与 QA

## 两阶段输出

### 阶段 A：资产规划

先输出可审阅的资产规划摘要和生产清单增量：

- 本轮读取的来源及定位；
- 新增、更新、合并或阻塞的资产；
- internal_key、中文 asset_id、类别、基准/变体、出现范围、production_need 和优先级；
- 来源层、视觉锚点、所需视图/状态、参考图职责与优先级、连续性关系、开放问题；
- 生产批次（每批不超过 5 项）和下一步确认问题。

默认把规划和生产清单同步写入当前项目的 visual-assets/资产规划.md 与 visual-assets/资产生产清单.md，但不保存完整 Prompt。

### 阶段 B：Prompt 交付

只有用户明确确认本批规划，或已经明确提供并确认一个边界清楚的单资产规格后，才输出 Prompt。每项外部结构如下：

1. 一行元数据：prompt_id、internal_key、模型适配目标、状态。
2. 参考图角色和来源定位摘要。
3. 一段独立可复制的代码块，代码块只含 Prompt 正文。
4. 一行 QA：母版字段齐全性、未决项、禁用/风险项、修订历史提示。

数量遵守生产清单批次；用户要求“下一批”时从下一个未交付批次继续，不重复旧 Prompt。

## 确定性检查

交付前逐项检查：

- 每个 internal_key 唯一且稳定；asset_id 在项目内唯一并遵守中文命名规则。
- 每项有来源定位或明确的 visual_design_proposal / unknown / conflict 标签。
- 每项已判断 image_reference、text_only、inline_temporary 或 undecided；只有需要图片或用户明确指定的资产进入 Prompt 队列。
- 角色/道具变体关联基准键；状态、集数、日/夜没有悄悄丢失。
- Prompt 包含场景/背景、主体、细节、视图/构图、参考图职责与优先级、连续性约束和输出意图；不包含视频运动或对白。
- 多任务或高密度资产已按基础、视图、状态或细节拆分，未把互相干扰的目标塞进同一 Prompt。
- 画幅只在用户要求、项目已确认或当前资产确有需要时出现；未凭空添加比例。
- 定向修改明确保持项和只修改项，局部返修没有无故重绘已确认内容。
- 每个 Prompt 独立成代码块，代码块外没有需要复制的隐含字段。
- 每轮不超过 5 项；prompt_id 新旧版本不冲突。
- 完整 Prompt 未写入 Markdown、缓存或日志；Markdown 只保存规划、清单、状态和来源。

## 生成闸门

仅当以下条件同时满足才可进入直接生成路径：

1. 用户明确说“直接生成/调用图像模型/生成这张图”等；
2. 相关资产规划，或边界清楚的单资产规格，以及本次 Prompt 已确认；
3. 模型目标、参考图授权、输出规格和保存位置明确；
4. 当前会话存在已授权且可调用的图像工具。

任一条件不满足时，只输出 Prompt 或提出确认问题。测试阶段不得调用图像工具。

## 边界与移交

发现项目上下文缺失、来源冲突、版权/品牌授权不明、要求生成视频分镜，或要求修改上游资料库时，停止受影响分支并给出明确移交对象：

- 缺少或冲突的剧情/项目事实 → $ai-video-project-context；
- 15 秒视频分镜、对白、动作时间轴 → $ai-video-storyboard-converter；
- 图像生成执行、上传、计费、重试 → 外部调用层/未来适配器；
- 客户项目的最终资产管理、审片和版本批准 → 项目负责人。
